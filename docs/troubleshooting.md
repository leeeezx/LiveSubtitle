# 常见故障与提交问题

## 扩展显示“未加载服务”或状态点是红色

1. 双击 `启动-流畅模式.cmd` 或 `启动-质量模式.cmd`。
2. 等待启动完成。
3. 回到视频页面刷新一次。

关闭 Chrome 不会自动启动字幕服务。下次使用时仍需要运行启动脚本。

## 视频正在播放，但没有字幕

- 确认视频声音从 Windows 当前默认播放设备输出。
- 在扩展中确认“显示字幕”已经开启。
- 如果刚更换耳机、蓝牙音箱或显示器，先停止服务，再重新启动。
- 尽量把系统和视频音量调到能够正常听清的程度。

## 启动时提示模型或服务加载超时

查看以下日志的末尾内容：

- `logs/llama.err.log`
- `logs/subtitle.err.log`
- `logs/host.log`

同时确认 `.venv`、`models` 和 `runtime` 仍位于项目根目录，并且端口 `8765`、`8766` 没有被其他程序占用。

## WebSocket 连接失败反复出现

这通常表示扩展正在重连，但本地字幕服务尚未启动或刚刚停止。服务启动完成后，扩展会自行恢复。已经停止服务时可以忽略这类连接错误。

## 停止后字幕服务仍在运行

再运行一次 `停止字幕.cmd`。如果问题仍然存在，请保留日志，并记录端口 `8765` 和 `8766` 的占用情况。

不要随意结束不确定用途的 Python 进程，以免影响电脑上的其他程序。

## 识别或翻译不够准确

按以下顺序排查：

1. 在扩展中选择正确的源语言。
2. 确认声音没有过小或失真。
3. 尽量只播放目标视频，避免提示音或其他声音混入。
4. 切换到质量模式重新测试。

实时字幕按声音片段处理。句子还没说完时出现轻微缺字或不完整，属于当前处理方式的正常限制。

## 提交问题时请附上

- 使用的是流畅模式还是质量模式；
- 视频语言、网站和大概出现问题的时间点；
- 扩展状态点的颜色；
- Chrome 扩展错误页中的完整错误；
- 相关日志最后约 30 行；
- 是否刚更换过耳机、蓝牙设备或视频输出设备。

不要上传个人账号、完整的私密视频链接、API Key 或本机私人文件。

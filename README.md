# 本地实时字幕

把 Windows 正在播放的声音识别并翻译成字幕，直接显示在 Chrome 视频页面上。

适合观看没有中文字幕的 YouTube 视频、网课和直播回放。语音识别与翻译都在本机完成，日常使用不需要 API Key。

![本地实时字幕工作流程](docs/workflow.svg)

> [!IMPORTANT]
> GitHub 仓库只包含源码和配置示例，不包含模型、Python 环境和 llama.cpp 运行组件。直接克隆后不能立即双击运行。

## 它能做什么

- 识别电脑当前播放的声音，而不是麦克风。
- 将英语、日语、韩语等语音翻译为简体中文。
- 在大多数普通 Chrome 视频页面上显示字幕。
- 同时显示原文和译文，并调整字号与位置。
- 把模型、配置和日志保存在本机。

## 使用前先确认

- **系统**：Windows 10 或 Windows 11，浏览器使用 Chrome。
- **显卡**：当前配置需要 NVIDIA 显卡；建议至少 6 GB 显存。
- **内存**：8 GB 可以尝试运行，16 GB 及以上更稳。
- **磁盘**：建议预留至少 10 GB，用于模型、运行组件和 Python 环境。
- **延迟**：字幕通常比声音慢约 2～4 秒。质量模式还会稍慢一些。

## 已经完成本机部署？

日常使用只需要三步：

1. 双击 `启动-流畅模式.cmd`，等待启动完成。
2. 打开或刷新视频页面。扩展状态点变绿后，字幕会显示在页面底部。
3. 使用结束后双击 `停止字幕.cmd`。

第一次使用还需要在 Chrome 中加载扩展，具体步骤见[使用说明](使用说明.md)。已经启动一种模式时，可以直接双击另一种模式完成切换。

## 流畅模式还是质量模式？

### 流畅模式

适合日常视频、访谈和语速正常的内容。字幕出现得更快，对显卡的压力也较小。

双击 `启动-流畅模式.cmd`。

### 质量模式

适合课程、长句或声音比较嘈杂的内容。识别会更仔细，但字幕稍慢，显卡占用也更高。

双击 `启动-质量模式.cmd`。

两种模式都使用本机 Whisper 识别语音，并通过 Hy-MT2 翻译。区别主要在声音分段长度和识别参数。

## 在扩展中调整字幕

点击 Chrome 工具栏中的“本地实时字幕”图标，可以直接改：

- 源语言和目标语言；
- 是否显示字幕；
- 是否同时显示原文；
- 字幕字号和显示位置。

改完后点击“应用设置”。如果知道视频使用什么语言，建议直接选择，不要使用自动识别。

## 声音从哪里采集？

工具听的是 **Windows 当前默认播放设备** 中的声音，不是麦克风。

- 视频声音必须从当前默认的音箱、耳机或显示器扬声器播放。
- 更换耳机、蓝牙设备或显示器后，如果突然没有字幕，先关闭字幕服务，再重新启动。
- 播放音量不宜太小。建议把视频和系统音量调到能正常听清的程度；声音失真或过小都会影响识别。
- 笔记本建议接通电源，并在显卡设置中使用高性能模式。
- 当前版本会听到默认设备上的所有声音。若同时播放游戏、聊天提示音或其他视频，它们也可能被识别；使用时尽量只播放目标视频。

## 隐私与联网

语音识别、翻译和字幕服务只监听本机地址 `127.0.0.1`。日常使用不需要把视频、声音或字幕上传到外部服务。

首次准备软件和模型时需要联网下载。准备完成后，可以在断网状态下使用当前的本机 Whisper + Hy-MT2 配置。

运行日志保存在本机的 `logs` 文件夹。除非你主动发送日志或配置，否则这些内容不会离开电脑。

## 常见问题

<details>
<summary>扩展状态点是红色，或者显示“未加载服务”</summary>

先双击一种启动脚本并等待启动完成，然后刷新视频页面。关闭 Chrome 不会自动启动字幕服务。

</details>

<details>
<summary>视频正在播放，但一直没有字幕</summary>

确认声音从 Windows 当前默认播放设备输出，并在扩展中检查“显示字幕”是否开启。如果刚更换过耳机或音箱，请停止服务后重新启动。

</details>

<details>
<summary>为什么字幕会比声音慢几秒？</summary>

程序需要先收集一小段声音，再完成识别和翻译。流畅模式通常更快；质量模式为了获得更稳定的结果，会多等待一些时间。

</details>

<details>
<summary>识别或翻译不够准确怎么办？</summary>

先选择正确的源语言，确认播放音量能够正常听清，再尝试质量模式。实时字幕按声音片段处理，句子还没有说完时出现轻微不完整属于正常现象。

</details>

<details>
<summary>启动超时或停止后无法重新启动</summary>

查看 `logs/llama.err.log`、`logs/subtitle.err.log` 和 `logs/host.log` 的末尾内容。更完整的处理方法见[排障说明](docs/troubleshooting.md)。

</details>
